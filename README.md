# Прогнозирование времени выполнения планов запросов PostgreSQL (MLOps-1)

Индустриальный учебный MLOps-проект по трекингу экспериментов и версионированию данных. Система прогнозирует фактическое время выполнения SQL-запросов (`actual_time_ms`) в СУБД PostgreSQL на основе статистических оценок стоимости и структуры дерева плана `EXPLAIN`.

## 🛠️ Архитектура и стек технологий
* **Управление окружением:** `Pixi` (изолированная бинарная среда на базе Conda-forge)
* **Версионирование данных (Data-as-Code):** `DVC` (с эмуляцией удаленного S3/локального хранилища)
* **Трекинг и реестр моделей:** `MLflow` (база метаданных SQLite + локальный Artifact Root)
* **Компиляция графа и продакшен-инференс:** `ONNX` & `ONNX Runtime`
* **Качество кода:** `Ruff` (педантичный линтинг и сортировка импортов PEP 8)

## 🚀 Быстрый запуск и воспроизведение

### 1. Подготовка изолированного окружения
Убедитесь, что у вас установлена утилита `pixi`. Инициализируйте проект и скачайте все зависимости:
```bash
pixi install
```

### 2. Синхронизация данных через DVC
Проект использует двухфазное версионирование. Для загрузки актуальной версии датасета `v2.0` (450 наблюдений на базе бенчмарков JOB и CEB) выполните pull из удаленного кэша:
```bash
pixi run dvc pull
```
*Для переключения на историческую базовую версию `v1.0` (300 строк) используйте:*
```bash
git checkout <хэш_коммита_v1.0>
pixi run dvc checkout
```

### 3. Запуск трекинг-сервера MLflow
Параллельно запустите централизованный сервер логирования экспериментов (сервер поднимется на `http://127.0.0.1:5000`):
```bash
pixi run mlflow-server
```

### 4. Запуск сквозного пайплайна машинного обучения
Все ключевые шаги автоматизированы с помощью декларативных тасок Pixi в `pixi.toml`. Выполняйте их последовательно:

* **Шаг А: Обучение модели и логирование** (DecisionTreeRegressor, подбор параметров через GridSearchCV, запись метрик R², MAE, RMSE в MLflow):
  ```bash
  pixi run train
  ```
* **Шаг Б: Экспорт в универсальный формат** (Загрузка лучшей версии из реестра MLflow, компиляция графа с динамическим батчем под Opset 15, проверка `onnx.checker` и верификация точности предсказаний с погрешностью `1e-5`):
  ```bash
  pixi run export-onnx --tracking-uri http://localhost:5000
  ```
* **Шаг В: Автономный инференс** (Запуск предсказаний на новых данных через ONNX Runtime, полная изоляция от MLflow):
  ```bash
  pixi run inference
  ```

## 📊 Признаковое пространство (Data Schema)
Модель принимает на вход **8 числовых признаков** структуры плана выполнения PostgreSQL:
1. `startup_cost` — Оценка стоимости подготовки к выполнению первой строки.
2. `total_cost` — Дисковая/процессорная стоимость полного плана по оценке планировщика.
3. `plan_rows` — Оценочное количество возвращаемых строк (кардинальность).
4. `plan_width` — Средняя ширина одной строки в байтах.
5. `join_nodes_cnt` — Количество операторов соединений (Hash/Merge/Loop Join).
6. `scan_nodes_cnt` — Количество операторов сканирования таблиц (Seq/Index Scan).
7. `index_scans_cnt` — Количество утилизируемых индексов в плане.
8. `filter_selectivity` — Селективность условий фильтрации предикатов (от 0 до 1).

**Целевая переменная (Target):** `actual_time_ms` — фактическое физическое время выполнения запроса ядром СУБД в миллисекундах.
